Release 26.11 ("Zokor", 2026.11/??)

Highlights

  • The default PostgreSQL version for new NixOS installations (i.e. with system.stateVersion >= 26.11) is v18.

  • The nixexprs.tar.xz tarball will be discontinued together with Nixpkgs 27.05 after 2027-12-31. Migrate to the nixexprs.tar.zst tarball instead.

    This affects for example users who pull Nixpkgs as a flake input from https://channels.nixos.org:

    -nixpkgs.url = "https://channels.nixos.org/nixos-26.05/nixexprs.tar.xz";
+nixpkgs.url = "https://channels.nixos.org/nixos-26.05/nixexprs.tar.zst";

    (Note: It is recommended to use these channel tarballs instead of github:NixOS/nixpkgs inputs in cases where specific revisions do not need to be pinned. Benefits include smaller download sizes and IPv6 support.)

  • Nix was updated to 2.35, which brings a lot of improvements and fixes. See the release notes for 2.35.

  • GNOME has been updated to version 51. Refer to the GNOME release notes for more details.

  • sing-box now supports NaïveProxy outbounds.

  • Enable Dux Calendar:

    {
  programs.dux-calendar.enable = true;
}

    Dux Calendar is a standalone calendar application with background sync and reminders. Enable session startup with programs.dux-calendar.systemd.enable.

  • Enable Dux Files:

    {
  programs.dux-files.enable = true;
}

Backward Incompatibilities

  • Nixpkgs no longer includes the Python package garth. Garmin changed its authentication flow, breaking new logins, and upstream no longer maintains Garth. Existing sessions can continue to work until their tokens expire.

  • Aurral upgrades from 2.x to 3.0.1. Before upgrading, run Aurral 2.13.0 against the existing data directory and wait for its database migrations to finish. On NixOS 26.05, use services.aurral.package = pkgs.aurral_213; after updating to a revision that provides aurral_213. If you use AUTH_PASSWORD, create an administrator account in the web interface before upgrading; Aurral 3 no longer reads AUTH_USER or AUTH_PASSWORD. Aurral 3 uses the official Lidarr plugin to download albums through Lidarr. To install it declaratively, set services.aurral.plugins = [ pkgs.aurralPlugins.lidarr ];. Read the upstream upgrade notes for other breaking changes.

  • easytier has been updated to 2.7.0 and is stricter about its configuration:

    • services.easytier.instances.<name>.configServer requires a full URL such as udp://example.com:22020/<token>; the bare <token> shorthand for the official server was removed.
    • The WireGuard portal no longer accepts client_cidr or wg://host:port/CIDR. Set wireguard_private_key and list the clients under vpn_portal_config.clients with a virtual_ip each.
    • Unknown keys in the [flags] table are rejected instead of being ignored, so a stale flag now stops the instance with failed to parse flags (upstream #2670).

  • immich-public-proxy has been updated to 4.x, which requires Immich 3.0.0 or newer and no longer reads some old config keys. Check services.immich-public-proxy.settings against the upstream upgrade notes.

  • services.music-assistant no longer ships the service API credentials that upstream bundles only in its official release builds. Providers that rely on them (spotify, qobuz, apple_music, theaudiodb, fanarttv) no longer work out of the box. Register your own credentials and pass them through MASS_APP_VAR_* environment variables or a MASS_APP_VARS_FILE JSON file, as described in services (M). The credentials are not covered by the Apache-2.0 license of the source code and may not be redistributed; see the upstream NOTICE.

  • arsenik has been renamed to kanata-config-aekeynox and updated to 0.4.0, following the upstream repository. services.arsenik has been replaced by services.kanata-config-aekeynox, whose options follow the sections of upstream's kanata.kbd; existing configurations must be migrated by hand.

  • services.freshrss blocks feeds on local and private networks, such as 127.0.0.1, LAN or NAT64 addresses, by default since freshrss 1.30.0. Allow self-hosted feeds, for example from RSS-Bridge, with services (F) or under System configuration in the web UI.

  • stirling-pdf has been updated to 3.1.0. The default server build retains built-in login and additional features, which include code under the Stirling PDF User License. Its package metadata now marks this build unfree, so users must allow unfree packages and review the upstream terms. Users who want the MIT-only build can set services.stirling-pdf.package = pkgs.stirling-pdf-free;. That build has no built-in login; restrict access through another trusted authentication layer before exposing it to other users.

  • services.autobrr.secretFile has been removed, as autobrr no longer uses a session secret since version 1.82.0. Remove the option from your configuration.

  • services.litellm fails to start without a master key since litellm 1.104.0, which refuses to serve unauthenticated requests. Set LITELLM_MASTER_KEY through services (L).

  • Artalk has been updated to 2.10.0. Its default configuration and data directory discovery changed; see the upstream migration guide when invoking artalk directly. The services.artalk module is unaffected.

  • services.opentelemetry-collector.validateConfigFile now defaults to true when the configuration comes from services.opentelemetry-collector.settings, so that configuration is validated at build time. It previously defaulted to isStorePath configFile, which is false whenever settings is used, so the validation never applied to that case.

    Configurations that reference confmap providers such as ${file:/path} or ${env:VAR} for secrets will now fail to build, because otelcol validate resolves those references and the files are not available in the build sandbox. Set services.opentelemetry-collector.validateConfigOverrides to override the affected properties for validation only, for example [ "extensions::bearertokenauth::token=stub" ], or set services.opentelemetry-collector.validateConfigFile = false to opt out.

  • LaSuite Docs has been upgraded to 6.x. The collaboration server has been replaced by a new component. Before rolling out the update, read the guide on how to migrate the data and the options' docs in the NixOS manual.

  • Canaille has been updated to 0.4.0. The release notes mention migration warnings.

  • Grafana with declarative plugins (services.grafana.declarativePlugins) no longer includes default data-sources as these were split out into apps. Make sure to add grafanaPlugins.tempo, grafanaPlugins.prometheus, grafanaPlugins.jaeger & grafanaPlugins.loki as needed.

    Users not using declarative plugins are not affected since Grafana installs those into the default plugin-path that is used unless declarative plugins are used.

  • boot.vesa has been removed. It was deprecated in 2020 because Xorg now works better with kernel modesetting. If you still need the legacy VESA 800x600 fallback, set boot.kernelParams = [ "vga=0x317" "nomodeset" ]; directly.

  • services.gitea-actions-runner is no longer compatible with the pkgs.forgejo-runner executable, migrate to services.forgejo-runner.

  • security.acme now uses lego 5.x. Existing ACME account state is migrated automatically. If you pass raw lego flags through security.acme.*.extraLegoFlags, security.acme.*.extraLegoRunFlags, or security.acme.*.extraLegoRenewFlags, update them for the lego 5.x CLI. In particular, lego renew has been replaced by the renewal mode of lego run. The certificate identifiers formed by domain and extraDomainNames must be unique and canonical to avoid repeated renewals. Use IDNA A-labels for internationalized domain names and RFC 5952 notation for IPv6 addresses. The security.acme.*.dnsPropagationCheck option has been split into two options:

    • security.acme.*.dnsAuthoritativePropagationCheck checks propagation by querying the zone's authoritative nameservers directly.
    • security.acme.*.dnsRecursivePropagationCheck checks propagation through recursive DNS resolvers, which may return cached records until their TTL expires. This option is disabled by default. Users who previously disabled dnsPropagationCheck should review which checks they want to disable and configure the corresponding new options. Disabling both preserves the previous behavior.

  • authentik has been updated to 2026.5.3, which changes the default listen address from 0.0.0.0 to [::]. IPv4-only deployments might need to adjust their listen settings. Example

Migrating fish functions to programs.fish.shellFunctions

Custom fish functions have historically been defined like so:

{
  programs.fish.interactiveShellInit = ''
    function backup --argument filename --description "Creates a backup copy of a file in the current directory."
      cp $filename $filename.bak
    end
  '';
}

The above example can be migrated via the following structured code block:

{
  programs.fish.shellFunctions = {
    backup = {
      modifiers = {
        description = "Creates a backup copy of a file in the current directory.";
        argument = "filename";
      };
      body = ''
        cp $filename $filename.bak
      '';
    };
  };
}

  • With system.etc.overlay.mutable = false, NixOS now ships an empty /etc/machine-id in the image. Previously the file was absent and systemd logged System cannot boot: Missing /etc/machine-id and /etc/ is read-only while ConditionFirstBoot fired on every boot. With this change, systemd now overlays a transient ID from /run/machine-id for the session, and systemd-machine-id-commit.service has ConditionFirstBoot so it writes the machine-id through to a persistent backing file when one is bind-mounted over /etc/machine-id. To persist the machine-id across reboots, bind-mount a writable file containing uninitialized over /etc/machine-id from the initrd, or set systemd.machine_id= on the kernel command line (use systemd.machine_id=firmware to derive a stable ID on hardware that supports it).
