Nixpkgs 26.11 ("Zokor", 2026.11/??)

Highlights

  • The {file}nixexprs.tar.xz tarball will be discontinued together with Nixpkgs 27.05 after 2027-12-31. Migrate to the {file}nixexprs.tar.zst tarball instead.

    This affects for example users who pull Nixpkgs as a flake input from https://channels.nixos.org:

    -nixpkgs.url = "https://channels.nixos.org/nixos-26.05/nixexprs.tar.xz";
+nixpkgs.url = "https://channels.nixos.org/nixos-26.05/nixexprs.tar.zst";

    (Note: It is recommended to use these channel tarballs instead of github:NixOS/nixpkgs inputs in cases where specific revisions do not need to be pinned. Benefits include smaller download sizes and IPv6 support.)

  • GCC has been updated from GCC 15 to GCC 16. This introduces some backwards-incompatible changes. Refer to the upstream porting guide for details.

  • Emacs has been updated to 31. This introduces some backwards‐incompatible changes; see the NEWS for details. NEWS can be viewed from Emacs by typing C-h n, or by clicking Help->Emacs News from the menu bar. It can also be browsed online.

  • sing-box now supports NaïveProxy outbounds.

Backward Incompatibilities

  • ccl has been updated from 1.13 to 1.14, adding native support for aarch64-linux and aarch64-darwin. The heap image and FASL formats have changed on all platforms; existing FASL files must be recompiled.

  • pmd has been updated from 6 to 7. Its command-line interface now uses subcommands: use pmd check, pmd cpd, pmd cpd-gui, pmd designer, and pmd ast-dump in place of the former standalone commands. The bgastviewer and designerold tools have been removed. See the PMD 7 migration guide for other breaking changes.

  • arsenik has been renamed to kanata-config-aekeynox and updated to 0.4.0, following the upstream repository. The configuration files moved from share/arsenik/ to share/kanata-config-aekeynox/ and follow the upstream file layout; kanata configurations that include them directly must be updated. See upstream's kanata.kbd.

  • roadrunner has been updated from 2025.1.15 to 3.0.0, which contains several breaking changes:

    • Middleware in http.middleware now run left to right; reverse the list to keep the previous order.
    • The Zipkin tracing exporter has been removed; use OTLP.
    • Goridge v4 removes the MessagePack codec; use JSON, protobuf, Gob, or raw payloads for RPC.
    • The AMQP driver requires named connections with config.connection, and config.version has been removed.
    • The TCP plugin is not supported; applications using tcp: must stay on RoadRunner v2025.

    See the upstream migration guide for details.

  • The dxvk Wine setup wrapper now uses DXVK 3.x on Linux. DXVK 3.x requires Wine 10.0 or newer and a Vulkan 1.4-capable driver, and removes the DXVK_FRAME_RATE environment variable; use dxvk.maxFrameRate instead. The native library is available as dxvk_3. The dxvk_1 and dxvk_2 packages remain available for older hardware and applications. See the upstream release notes for details.

  • stirling-pdf has been updated from 2.14.3 to 3.1.0. The default server build still includes login, but it now has an unfree license because those features contain proprietary code. Users must allow unfree packages and review the upstream license. The MIT-only server is available as pkgs.stirling-pdf-free; it does not include built-in login. Set services.stirling-pdf.package = pkgs.stirling-pdf-free; to use it with the NixOS service.

  • moon has been updated to 2.x and needs manual migration. See the migration guide for instructions.

  • readest now uses CEF instead of WebKitGTK on Linux. Wayland sessions require XWayland.

  • paperless-manage now uses runuser instead of automatically calling sudo to set user/group before running. Invoke the script with sudo paperless-manage or an equivalent elevation tool of your choice

  • OpenSSL now prefers the system CA bundle at /etc/ssl/certs/ca-certificates.crt on both Linux and Darwin, falling back to /nix/var/nix/profiles/default/etc/ssl/certs/ca-bundle.crt only when the system bundle is absent. Previously, Darwin used the default Nix profile bundle directly. An existing but unreadable or invalid system bundle does not trigger the fallback. Explicit NIX_SSL_CERT_FILE and SSL_CERT_FILE overrides still take precedence.

  • hpx has been updated from 1.11.0 to 2.0.0. C++20 is now required, tag_invoke customization has been removed, and HPX's senders/receivers implementation has been replaced by stdexec. See the upstream release notes.

  • hyperfine has been updated from 1.21.0 to 2.0.0, which contains several breaking changes:

    • Benchmarked commands are now executed directly instead of through an intermediate shell. Pass -S/--shell=default to restore the previous behavior.
    • The --export-json format has changed (schema version 2); tools consuming the exported JSON must be updated.
    • --time-unit/-u, --sort, --reference and --reference-name have been removed. Units are now selected with --metrics, and the first command is always treated as the reference.
    • The Markdown, AsciiDoc, org-mode and CSV export formats have changed.

    See the upstream changelog for details.

  • atlantis has been updated to v0.49.0 which includes a number of breaking changes to address security vulnerabilities. A fully list is available in the v0.49.0 release page

  • yeswiki has been updated from 4.4.2 to 4.6.7 and now requires PHP 8.3 or newer. The release also removes legacy JSONP endpoints and changes several security-sensitive operations from GET to POST with CSRF tokens. Review the upstream 4.6.7 release notes before upgrading custom themes or integrations.

  • rauthy has been updated to minor version 0.37. This release includes breaking changes, see the upstream release notes for more details.

  • zabbix.<package> now defaults to version 7.4. If you want to keep using Zabbix 6.0, use pkgs.zabbix60.<package>. Note that Zabbix 6.0 is in limited support, and will be deprecated on February 28, 2027. Consider upgrading.

  • zabbix-agent2-plugin-postgresql is now moved to zabbix{60,70,74}.plugins.postgresql.

  • Official Zabbix plugins (ember-plus, mongodb, and mssql) have been added under zabbix{60,70,74}.plugins.<plugin>.

  • perlPackages.NetOAuth has been updated from 0.28 to 0.33. Callers that verify messages must now set allowed_signature_methods per message or configure @Net::OAuth::ALLOWED_SIGNATURE_METHODS; verify otherwise throws an exception. See the upstream changelog for details.

  • geeqie has been updated to 3.3, which ports it from GTK3 to GTK4. All --action command-line parameters have changed and some default shortcuts now follow GNOME conventions. On first start, shortcuts and geeqierc.xml are converted one way, and the old file is kept as a backup. Standalone collection windows were removed in 3.2. See the upstream NEWS.

  • Support for x86_64-darwin has been dropped, due to Apple’s deprecation of the platform and limited build infrastructure and developer time. We will no longer build packages for the platform or support building them from source.

    The Nixpkgs 26.05 stable branch will still maintain platform support and binaries will be built until it goes out of support at the end of 2026. Users of x86_64-darwin will receive an error message explaining how to switch to 26.05.

    By the time of this release, Homebrew will offer only limited Tier 3 support for the platform, but MacPorts will likely continue to support it for a long time. We also recommend users consider installing NixOS, which should continue to run on essentially all Intel Macs, especially after Apple stops security support for macOS 26 in 2028.

  • ocamlPackages.buildDunePackage now builds packages with out, dev, man and doc outputs by default, unless they set outputs. The OCaml libraries are installed into dev, man pages into man, documentation into doc, and out only contains what is needed at runtime, such as executables. This removes build-time only OCaml dependencies from the closure of tools like patdiff. Code that refers to ${ocamlPackages.foo}/lib/ocaml must use ${lib.getDev ocamlPackages.foo}/lib/ocaml instead. Installing such a library into a profile or environment (for example with home.packages, environment.systemPackages or nix profile add) no longer provides its lib/ocaml directory; install ocamlPackages.foo.dev instead.

  • The bin and lib outputs of ocamlPackages.odoc, ocamlPackages.crunch, ocamlPackages.mdx and ocamlPackages.tw were removed. Use the package itself for the executables, and its dev output for the OCaml library.

  • bundlerApp now sets __structuredAttrs = true for its result package. Out-of-tree packages passing postBuild to bundlerApp should examine if their postBuild commands are compatible with structured attributes.

  • praat has been updated to 7.x.x, which changes the location of the settings file, buttons file, and plug-ins to standardized locations for each platform. This is a breaking change for plug-in writers and users of the sendpraat subroutine.

  • astal, ags and ags_1 have been dropped, as they were largely untested and the main and only consumer (hyprpanel) has been also dropped. Instead, use upstream flake.

  • databricks-cli has been updated from 0.290.2 to 1.x.x, the first major release. OAuth tokens for interactive logins (auth_type = databricks-cli) are now stored in the OS-native secure store by default (Secret Service on Linux) instead of ~/.databricks/token-cache.json; cached tokens from older versions are not migrated, so run databricks auth login once per profile after upgrading. To keep the previous file-backed storage, set DATABRICKS_AUTH_STORAGE=plaintext or add auth_storage = plaintext under [__settings__] in ~/.databrickscfg. Additionally, the vector_search_endpoints DABs resource renamed min_qps to target_qps (and the vector-search-endpoints command renamed --min-qps to --target-qps). See the upstream changelog for details.

  • home-assistant-custom-lovelace-modules.card-mod has been removed in favor of its successor UIX, which is packaged as home-assistant-custom-components.uix. Since UIX is an integration rather than a Lovelace module, move it from services.home-assistant.customLovelaceModules to services.home-assistant.customComponents. Existing card_mod: configuration keeps working.

  • mermaid-cli has been updated to 12.0.0, which changes default diagram themes and layouts. To keep the previous appearance, set layout: dagre, theme: default, and look: classic in the Mermaid configuration. The --width and --height options have been replaced by --size. The --pdfFit option has been removed: PDFs now fit the diagram by default; use --pdf-paper-format=Letter for the previous default paper size. The --iconPacks option now requires locally installed packages; use --iconPacksNamesAndUrls for explicit icon pack URLs, including file:// URLs. Custom CSS passed through --cssFile now uses Mermaid's themeCSS. SVG files embed fonts by default; use --no-font-embed to disable this. See the upstream release notes for details.

  • Gradle 7 has been removed because it is end-of-life. Please upgrade to a newer version of Gradle.

  • drasl 4.0.0 has restructured its configuration options for user registration. See the release notes.

  • hurl has been updated to 8.x.x which has some breaking changes. See upstream changelog for details.

  • logseq has been updated to version 1.0.0, which upstream renamed to logseq-og. Due to the rename, the config directory moved to $HOME/.logseq-og. Users will need to point logseq-og to their Markdown files again, or move $HOME/.logseq to the new config location.

  • amtterm has been updated to 1.8. amtterm and amtider now connect with TLS on port 16995 by default, and verify the certificate only when given -C <cacert>. Use -P to connect without TLS on port 16994 as before, for AMT that doesn't have TLS configured. AMT accepts only TLS from CSME 16.1 on. amttool no longer verifies certificates for HTTPS connections.

  • The existing wasm32-wasi target has become wasm32-wasip1 and pkgsCross.wasi32 has become pkgsCross.wasm32-wasip1, aligning with LLVM's nomenclature. Aliases are in place and old forms will continue to be parsed but there might be some breakage if you're relying on the exact form of these (e.g., in sysroot paths).

  • sing-box has been updated to 1.14.0, which has removed some deprecated options. See upstream documentation for details and migration options.

  • xray The allowInsecure option is no longer supported.

  • buildGoModule.goModules now sets __structuredAttrs = true; and strictDeps = true; Out-of-tree packages passing arguments incompatible with structured attributes should convert them to be compatible.

  • gotosocial has been updated to 0.22.0. This release contains a very long database migration, which should not be cancelled or interrupted under any circumstances.

  • Postgres users: Following the migration, if you encounter slowdown on Postgres specifically (ie., timing out while loading timelines) you may need to run some manual database maintenance steps. Please check https://docs.gotosocial.org/en/stable/admin/database_maintenance/#postgres.

  • lean now refers to Lean 4 instead of Lean 3. Lean 3 is unmaintained and has been removed from Nixpkgs.

  • lego has been updated to 5.x, which has a changed CLI and state layout. See upstream's v4 to v5 CLI migration guide for details.

  • tmux has been updated to 3.8, which changes some defaults: the mouse option is now on, and built-in light and dark themes replace the previous default colours (set the theme option to terminal to restore them). display-panes -b has been removed. See the changelog for details.

  • xsecurelock no longer supports authentication via htaccess files (~/.xsecurelock.pw) or via the pamtester program by default. Only the recommended PAM module is supported unless rebuilt with withHtaccess or withPamtester.

  • keychain has been updated to 3.x.x, which is a major and breaking rewrite of the program, including its CLI arguments. See v3 release notes for details and migration.

  • minio-client is no longer maintained and scheduled for removal in 27.05.

  • forgejo has been updated to major version 17, which includes breaking changes. See the upstream release notes for more details.

  • vinyl-cache has been updated from 9.0.x to 9.1.x. See the project's update instructions for the few breaking changes it entails.

  • python3Packages.django-health-check has been updated to major version 4. See its migration guide and changelog for breaking changes.

  • jmtpfs has been removed due to lack of maintenance and fuse3 support.

  • python3Packages.tensorflow-build and libtensorflow have been removed, as they had been broken for years. Use python3Packages.tensorflow (tensorflow-bin) instead. The withTensorflow options of ffmpeg and snips-sh have been removed accordingly.

  • halloy now builds with Tor proxy support by default using Arti, which can be disabled by overriding withTor with false.

  • postgresqlPackages.anonymizer has been updated from 2.4.1 to 3.2.2. The extension must be dropped and recreated, and masking no longer runs as a superuser. See the upgrade notes for details. pg-dump-anon has been removed as it was removed upstream. Use pg_dump with a masked role instead.

  • landrun was updated to 0.1.17, which included breaking changes, reference the breaking changes section in the landrun release notes.

  • gimp2 has been removed due to being unmaintained upstream, and depending on the deprecated GTK2 library. Along with that, all GIMP plugins in the gimpPlugins set that only worked with gimp 2.0 have been removed as well.

  • libgdata has been removed, as it was archived upstream and relied on the insecure libsoup 2.4.

  • mcphost has been removed, as it was archived upstream and declared unmaintained.

  • fflogs has been removed because it was no longer functional. Users should switch to archon-lite.

  • keycloak.plugins.scim-for-keycloak has been removed. The upstream open-source project is end-of-life and its last release targets Keycloak 20, which is incompatible with the packaged Keycloak.

  • keycloak.plugins.scim-keycloak-user-storage-spi has been removed. Upstream has moved the plugin into Keycloak itself as the experimental ipatuura federation provider and no longer maintains the standalone repository.

  • The gtk2 package was marked broken because it will be removed in NixOS 27.05. Any package using it must be migrated to gtk3 or gtk4 or it will also be removed in NixOS 27.05.

  • services.mysql now sets root@localhost authentication to auth_socket when used with mysql or percona-server. Existing deployments will also be adjusted if possible. See the security advisory GHSA-6qxx-6rg8-c4p8 for more information.

  • Usability of services.kavita has been improved:

    • Managing secrets or credentials within services.kavita has been improved to allow users to load more than 1 secret into the service with services.kavita.credentials.
    • services.kavita.tokenKeyFile has been renamed to services.kavita.settings.TokenKey and accepts a string. The value of services.kavita.settings.TokenKey should be updated with placeholder text, such as @token_key@; and re-defined in services.kavita.credentials. Refer to module documentation for more information.
    • services.kavita now properly links default e-mail templates from upstream. If there are existing files in EmailTemplates directory, default e-mail templates will not be symlinked.

  • sqlitestudio has been renamed to letos to reflect upstream changes. See Letos: Name rebranding for more information.

  • The Dank Linux suite has been renamed to Dux Labs and updated to v2.0.0. The packages have been renamed to match upstream:

    • dms-shell to dux-shell
    • dms-greeter to dux-greeter
    • dankcalendar to dux-calendar
    • dsearch to dux-search
    • dgop to dux-gop

    The old package names remain available as deprecated aliases, executable names are unchanged. Dux Shell now uses dms instead of DankMaterialShell for its XDG configuration, state, and cache directories.

  • zerofs has been updated from 1.x to 2.x which is a breaking change. Volumes created by earlier releases are refused at open with a clear error. There is no migration tool; older volumes remain readable and writable by the release that created them.

  • python3Packages.buildPythonPackage and python3Packages.buildPythonApplication now warn in the presence of unittestFlagsArray. Please use unittestFlags instead. If modifying the Nix expression is not feasible, users can remediate the warning by overriding unittestFlagsArray with null or [ ].

  • keycloak.plugins.keycloak-metrics-spi has been removed. Keycloak exposes Prometheus metrics natively on its management interface; enable them with the metrics-enabled setting (and event-metrics-user-enabled for login and event counters). See Gaining insights with metrics.

  • alps has been rewritten upstream, see upstream repository for documentation.

  • writers.makeDataWriter has been removed. It has been deprecated since 2023. Use pkgs.writeTextFile instead.

  • bosun has been removed as it is no longer maintained upstream. the corresponding monitoring options has been removed.

  • python3Packages.starlette-admin v1.0.0 has released, which mainly refactors internals and adds a large set of new features. The high-level API is mostly unchanged, but users migrating from v0.17 may want to view the migration guide.

  • uhttpmock providing 0.0 ABI was removed. uhttpmock_1_0 providing 1.0 ABI was renamed to uhttpmock and uhttpmock_1_0 was kept as an alias.

  • collectd's varnish plugin support has been removed, as varnish has been removed in favor of vinyl-cache.

  • himalaya has been updated from v1.2.0 to v2.0.0, which introduces breaking changes. See the release notes and the migration guide.

  • proton-cli has been updated from 2.2.3 to 3.4.0, and installs its command as proton, with proton-cli kept beside it as a symlink. 3.0.0 reworked the command line - --output is now the response format, secrets are no longer accepted as flag values, and several subcommands moved - so scripts need a review against the upstream changelog.

  • comodoro has been updated from 0.1.2 to 2.0.0, which brings the breaking changes of both major releases; see the upstream changelog.

  • filebrowser-quantum has been updated from 1.5.2-stable to 2.0.2-stable, which requires a database migration and config changes. See the migration guide and the upstream changelog before upgrading.

  • tengine has been removed as it has seen seriously delayed responses to security vulnerabilities.

  • jellyfin has been upgraded to major version 12, which contains breaking changes. See the upstream blog post for more information on how to safely upgrade.

  • writeTextFile now uses structured attributes and passAsFile is no longer used or supported.

  • nix-serve-ng (and haskellPackages.nix-serve-ng) is now built against Lix instead of CppNix, following upstream which has switched to Lix as its supported Nix implementation.

  • buildPythonPackage and buildPythonApplication now set __structuredAttrs = true by default. You can explicitly set __structuredAttrs = false in packages broken by this change.

  • The coqPackages and coq attributes, along with their versioned variants for Rocq ≥ 9.0, are now deprecated aliases for rocqPackages and rocqPackages.coq (the latter providing Coq compatibility binaries, use rocq-core if you do not need them). They still work but emit a warning. Users should migrate to rocq-core and rocqPackages. Older Coq 8.x attributes such as coq_8_20 and coqPackages_8_20 remain unchanged.

  • Linux kernel configuration has been moved out of the linux-kernel field of the platform structure into the kernel builders:

    • linux-kernel.name has been removed.
    • linux-kernel.target is available as the target parameter and passthru attribute on the kernel builders.
    • linux-kernel.installTarget has been removed, as it should not be necessary to customize.
    • linux-kernel.DTB is available as the buildDTBs parameter and passthru attribute on the kernel builders.
    • linux-kernel.{autoModules,preferBuiltin,extraConfig} were already available as kernel builder parameters.

  • The img argument of vmTools has been renamed to kernelImage, as it collided with the top-level img package. Additionally, the kernel module tree used inside the VM has been split out of the kernel argument into a new kernelModules argument (defaulting to kernel). Callers that overrode kernel with a module tree (e.g. from pkgs.aggregateModules) to make extra modules available must now pass it via kernelModules instead, keeping kernel pointing at a bootable kernel derivation.

  • vmTools no longer provides disk images for end-of-life distributions: fedora42x86_64, debian11i386 and debian11x86_64 have been removed.

  • The JetBrains IDEs have all been moved to the top-level:

    • jetbrains.idea and jetbrains.idea-oss have been renamed to intellij-idea and intellij-idea-oss respectively.
    • jetbrains.mps has been renamed to jetbrains-mps.
    • jetbrains.gateway has been renamed to jetbrains-gateway.
    • All other IDEs have directly moved to the top-level with no prefix (e.g. jetbrains.pycharm -> pycharm).
    • jetbrains.plugins remains unchanged for now.

  • service.soju.enableMessageLogging option has been removed in favor of messageStoreDriver which supports enabling the db storage backend.

The default target version used by swiftc on Darwin is the operating system major version. This value may be overridden by the build system (e.g., SwiftPM defaults to 10.13 instead).   • buildFHSEnv, appimageTools.wrapAppImage, and appimageTools.wrapType2 now support the finalAttrs pattern. When using wrapAppImage, it is now recommended to pass the extracted AppImage to the contents attribute (instead of src), to avoid shadowing src. Passing the extracted contents to src is now deprecated and will be removed in a future release.

Package-URLs allow reliably identifying and locating software packages. Maintainers of derivations using the adapted fetchers should rely on the drv.src.meta.identifiers.v1.purl default identifier and can enhance their drv.meta.identifiers.v1.purls list once they would like to have additional identifiers. Maintainers using fetchurl for drv.src are urged to adapt their drv.meta.identifiers.purlParts for proper identification.

  • nextpnr introduced support for the nexus and gatemate architectures. Building support for each individual architecture can be configured using the package parameters.

  • mastodon has been updated to 4.7. The 4.7.0 release notes mention some unusually long running migrations.

  • nixos-version now supports --kernel-version to show the configured kernel version and --specialisations to list specialisation names separated by spaces. Its --json output also includes this information when available.

Breaking changes

  • fittrackee 1.0.0 now requires postgres with postgis. The upgrade guide has steps to prepare for this upgrade.

Thus, factor applications using extra/pcre must switch to extra/pcre2 or have to add the old pcre library back via the extraLibs attribute.   • navidromePlugins.apple-music now uses a bundleName attribute which sets the plugin's name to match the plugin's documentation for easier use. You will need to update your Agent from apple-music-plugin to apple-music as noted in their docs.
